**Отправьте задачу на другой Mac. Получите Git-ветку с результатом.**

Запускайте Codex, Cursor, OpenCode или Claude Code на свободных Mac через SSH. Каждая задача получает отдельный Git worktree. Можно включить автоматическую интеграцию в ветку на origin или, отключив интеграцию, получить результат для ручной проверки.

https://github.com/user-attachments/assets/b9ae9408-8f45-4da9-b997-b1d851f79283

## Что нужно

- Два Mac с Apple Silicon и Git: ноутбук и хотя бы один рабочий Mac.
- Доступ к рабочему Mac по SSH-ключу и включённый Remote Login. Во время выполнения задач Mac должен оставаться включённым и не уходить в сон.
- Один установленный агент на рабочем Mac с выполненным входом в аккаунт. В примерах используется Codex.
- Для автоматической интеграции на каждом рабочем Mac нужен Apple `/usr/bin/git` версии 2.43 или новее, то есть macOS 26 или Xcode/Command Line Tools 26. В macOS 15 с инструментами Xcode 16 поставляется Git 2.39.5, и интеграция там блокируется. Обычные задачи при этом выполняются. Программа вызывает `/usr/bin/git` по абсолютному пути, поэтому Git из Homebrew не считается.

[Подготовка рабочего Mac](docs/setup-macos-worker.md) описывает SSH, агентов и инструменты проекта. Запускайте доверенные задачи: агент имеет доступ к файлам и учётным данным аккаунта на рабочем Mac.

Обновляете установку, где выполнялись пакетные команды на файловых snapshot? [Сначала завершите старые задания](docs/legacy-batch-state.md#drain-before-upgrading); ручная очистка ограничена конкретными устаревшими артефактами.

## Быстрый старт

Все команды ниже выполняются на **ноутбуке**.

### 1. Установите CLI на ноутбук

Соберите из исходников с помощью Rust и Git:

```bash
git clone https://github.com/kirchik95/mac-worker.git
cd mac-worker
cargo build --locked --release
mkdir -p "$HOME/.local/bin"
install -m 755 target/release/worker "$HOME/.local/bin/worker"
export PATH="$HOME/.local/bin:$PATH"
```

Добавьте строку `export PATH` в `~/.zprofile`, чтобы команда была доступна в новых терминалах. Панель управления входит в сборку. [Варианты установки и релизы](docs/getting-started.md#1-install-the-cli-on-your-laptop).

### 2. Подключите рабочий Mac

```bash
worker init yourname@mini.local --agent codex
```

Замените SSH-адрес на свой. `init` установит компонент mac-worker на рабочий Mac и проверит вход агента в аккаунт. Если команда сообщит о недостающем шаге настройки, выполните его и повторите запуск. Для другого агента укажите его через `--agent` здесь и при отправке задачи.

### 3. Получите первую ветку

Откройте свой проект — Git-репозиторий, в котором есть хотя бы один коммит:

```bash
cd /path/to/your/project
worker task submit --agent codex --wait \
  --prompt "Create SETUP_CHECK.md containing: mac-worker works."
```

Если в проекте уже настроен параметр `[task] integrate`, добавьте к этой команде `--no-integrate`, чтобы проверочный файл не попал в целевую ветку.

Подставьте полученный идентификатор задачи вместо `<task-id>`:

```bash
worker task result <task-id>
worker task diff <task-id> --stat
worker task fetch <task-id>
```

`result` печатает итог и краткое описание работы. `diff --stat` сравнивает базовый коммит задачи с опубликованным результатом. В этом примере интеграция отключена: после хода с итогом `done` задача закрывается по умолчанию (`--close-on done`), и рабочее пространство на рабочем Mac удаляется; `diff` по-прежнему работает по базовому и результирующему коммитам, которые остаются в зеркале проекта на этом Mac. Если сборка мусора уже удалила эти коммиты, `diff` завершается ошибкой `RESULT_NOT_RETAINED` с сообщением `task workspace is closed and its result is no longer retained`. `fetch` выведет Git-ссылку на результат для проверки. Текущая рабочая копия останется прежней. При ручной работе вы сами решаете, что вливать. По умолчанию задача берёт исходники из `HEAD`; для незакоммиченных изменений нужен [`--wip`](docs/getting-started.md#manual-cli).

Продолжить сессию Codex или Claude Code с ноутбука: `worker task submit --from-session codex[:<uuid>] --prompt "…"` (для Claude Code — `claude[:<uuid>]`). Если в рабочей копии есть незакоммиченные изменения, добавьте `--wip`. [Продолжение сессии ноутбука в пуле](docs/usage.md#continue-a-laptop-session-in-the-pool).

## Автоматическая интеграция

Интеграция включается явно и по умолчанию отключена. Добавьте настройки в `.worker.toml` проекта, чтобы использовать его собственный origin:

```toml
[task]
integrate = "main"
verify_merge = "never"
```

Отправляйте задачи по одной или пакетом как обычно. Каждая подходящая завершённая задача интегрируется автоматически, без подтверждения принятия. У нового merge-коммита первый родитель — прежняя вершина целевой ветки, а второй — результат задачи; для уже достижимого результата новый коммит не нужен. При конфликте тот же агент продолжает работу на том же Mac и в той же сессии. Если восстановление заблокировано, посмотрите `worker task status <id>`, устраните причину и выполните `worker task integrate <id>`.

Настройки задачи имеют приоритет над настройками пакета, а те — над настройками проекта. Флаг `--no-integrate` при отправке отключает унаследованную интеграцию. Проверка объединённого результата по умолчанию — `never`; ходы для разрешения конфликтов и проверки расходуют общий лимит `max_followups`. База должна быть коммитом, уже достижимым из целевой ветки; `--wip` несовместим с интеграцией.

`worker controller drain` приостанавливает передачу обычных ходов исполнителям, новые этапы интеграции и постановку вспомогательных ходов; уже допущенный этап или запущенный ход завершается до перехода в паузу. `worker controller drain --off` возобновляет и обычные ходы, и интеграцию. Отключение контроллера приостанавливает только интеграцию; после повторного включения она остаётся на паузе до `drain --off`. Перезапуск контроллера не создаёт паузу.

> **Предупреждение об откате:** откат helper ниже `task.integration` дольше 7 дней может уничтожить рабочее пространство восстановления приостановленной или заблокированной интеграции.

Откат helper также ставит интеграцию на паузу. Настройки, проверки, ограничения, сборка мусора простаивающих задач и завершение закрытой задачи только наблюдением описаны в [справочнике по автоматической интеграции](docs/usage.md#automatic-integration).

Когда интеграция отключена, заблокирована или от неё отказались, сохранённый результат по-прежнему можно просмотреть и получить для ручной проверки. Ручной `task close` сохраняет результат и прекращает незавершённую интеграцию; эта команда не разрешает слияние.

## Повседневная работа

Откройте панель управления, чтобы следить за рабочими Mac и задачами:

```bash
worker dashboard
```

Чтобы поручать работу агенту на ноутбуке, [установите два навыка для работы с пулом](docs/getting-started.md#ask-your-laptop-agent) и попросите:

> Отправь задачу в пул: создай SETUP_CHECK.md со строкой mac-worker works. Дождись результата и покажи ветку.

По умолчанию очередью управляет ноутбук. Включите [удалённый контроллер](docs/usage.md#remote-controller), чтобы очередь и процессы управления задачами работали на постоянно включённом Mac. С контроллером `worker notify --follow` показывает уведомление на ноутбуке, когда задача завершена или ждёт ответа, а `worker events -f` выводит поток событий контроллера.
